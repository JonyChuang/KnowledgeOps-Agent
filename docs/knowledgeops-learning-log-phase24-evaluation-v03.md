# 阶段 24：500 条检索与 Chat 模型联合测评

## 目标

v0.3 不再只验证“能不能找到知识库文档”，而是同时验证两件事：RAG 检索是否能在大量相近资料中定位正确文档；Chat 模型是否会为不同员工意图选择正确的 Agent 工具。

## 数据设计

评测集包含 100 份资料和 500 条检索题。25 个业务主题各扩展为标准策略、申请处理、异常响应、定期复核四种相近文件。每份文件有直接问题、自然语言改写、边界区分、操作记录和时效要求五种题型。

因此 500 并不是把同一句话复制 500 次。相同主题词会出现在不同流程中，系统必须根据“申请、异常、复核”等意图及具体规则找到正确资料。

## Chat 模型如何测

100 条 Agent 用例包括普通聊天、知识库查询、我的工单列表、指定工单详情和建单草稿。评测只调用模型做第一轮工具选择，不执行知识库工具、不读取真实工单、更不会创建工单。

报告中的三个 Chat 指标分别是：工具精确选择率、工具参数是否符合 JSON Schema、建单场景是否坚持只生成草稿并等待用户确认。

## 成本与边界

完整运行大约需要 1,500 次 Embedding 调用与 100 次 Chat 调用。它是真实模型评测，不应为了省时填写估算值。运行完成前，报告没有分数；运行完成后，也只能说明该版本的脱敏 Gold 集表现，不能替代生产日志和人工评审。

## 面试表达

“我把离线测评从小样本检索扩展到 500 条带证据的检索题，并加入 100 条 Function Calling 场景。检索测试比较向量、BM25、混合检索和重排序；Agent 测试独立检查工具路由、参数 schema 和人工确认门禁。两部分使用不同指标，避免把回答流畅度误当成业务动作正确性。”
