# 阶段 21：扩展到百题规模的离线评测集

## 为什么不能只增加问题数量

如果把同一个问题换几个说法凑到一百条，指标看起来更稳定，但无法证明检索系统具备更强的能力。真正能区分系统水平的是“相邻规则是否能分清”：例如密码忘记与账号锁定、普通临时权限与破窗权限、VPN 网络故障与 VPN 身份认证故障。

## v0.2 的设计

v0.2 包含 24 份脱敏虚构 Markdown 资料、120 条检索题、24 条 Agent 工具选择题和 12 条安全门禁场景。每份资料对应五类问题：直接流程、自然语言改写、相邻主题对比、工单操作和时效边界。因此检索题不是简单重复，而是覆盖了不同的提问方式和易混淆点。

Gold 集继续使用 `source_name` 作为证据标识。这样题目要求命中正确文档，不依赖每次切分产生的随机 chunk ID。评测实现会对同一来源的多个分块去重，避免 nDCG 被重复证据抬高。

## 哪些结论可以说，哪些不能说

可以说：项目有一套版本化、可复现、可扩展到百题规模的离线评测基础设施，并能比较向量、BM25、混合检索和重排序的召回、排序质量与延迟。

不能说：v0.2 尚未运行前，不能宣称某种方案在百题集上的分数或优于另一种方案。即使运行后，它也是脱敏合成资料的结果，仍需要真实业务日志和人工标注来补充验证。

## 面试表达

“早期四题或六题的评测只能验证链路。为了让检索对比更可信，我把评测扩展为 24 份相近主题资料和 120 条带证据标注的问题，并强制覆盖同义改写、流程、时效和相邻政策边界。这样可以定位系统究竟是语义理解不足、关键词偏置，还是把相近制度混淆了。所有分数都由固定版本的 Gold 集实际运行产生，不手工填写。”
