# 阶段 6：员工工作台、搜索、通知与反馈

## 用户问题

用户不应该每次进入系统都从菜单逐页寻找信息。员工真正关心的是：我有哪些未完成工单、资料是否已经可用、最近和 Agent 谈过什么、是否有新的处理结果。

## 阶段目标

- 用一个工作台聚合当前用户的工单、知识库、索引健康和最近会话。
- 让全局搜索在一个入口返回资料、图谱实体、会话和工单。
- 将工单处理和个人操作转成可读、可确认的通知。
- 提供收藏、最近访问和 Agent 回答反馈，让系统能形成持续改进信号。

## 工作台为什么使用聚合接口

工作台包含多种数据。如果前端分别请求工单、知识库、文档、会话，容易产生加载顺序不一致和大量往返。`GET /dashboard` 由后端按当前用户一次聚合所需摘要，前端只负责渲染；点击“询问 Agent”“查看知识库”“管理全部知识库”等按钮再跳转到对应的专业页面。

## 数据范围

| 功能 | 数据范围 | 说明 |
| --- | --- | --- |
| 工作台工单与会话 | 当前用户 | 不能用展示名称作为权限依据 |
| 常用知识库与索引健康 | 组织共享知识库 | 当前项目未实现多租户文档 ACL |
| 全局搜索 | 当前用户可见的个人数据 + 共享资料 | 返回结果按类别展示 |
| 收藏、最近访问、反馈 | 当前用户 | 用于个人效率与后续质量分析 |
| 通知 | 当前用户 | 来自工单和协作事件 |

## 最小复现

1. 登录员工账号，创建至少一张工单和一段 Agent 对话。
2. 打开“我的工作台”，确认近期工单、常用知识库和本次会话都有对应摘要。
3. 点击“询问 Agent”“查看知识库”“管理全部知识库”和“前往文档索引”，确认跳转到正确页面。
4. 在“全局搜索”检索一个关键词，将结果加入收藏；进入“收藏与最近访问”确认数据只属于当前账号。
5. 由服务台更新工单后，回到员工账号检查通知中心的未读提醒。

## 常见误区

- **把工作台做成第二个完整工单页。** 工作台应该突出待处理摘要和下一步操作，详情留给专业页面。
- **搜索时只查标题。** 这会失去知识库正文和历史上下文的价值；聚合搜索需要明确来源类型。
- **把“未读数”只放在前端变量。** 刷新后会丢失，应该由通知数据的已读状态计算。

## 面试表达

“工作台不是静态仪表盘，而是当前用户的操作入口。我用后端聚合接口减少前端拼装和请求数量；通知、收藏、最近访问和 Agent 反馈都绑定用户，既提升个人效率，也为后续分析知识库和 Agent 质量留下可追溯信号。”
