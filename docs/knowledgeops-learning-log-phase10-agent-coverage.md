# 阶段 3 学习日志：Agent 的知识库覆盖范围提示

## 1. 这次发现了什么问题

用户向 `Engineering Docs` 提问“帮我总结知识库中的工程规范”时，页面只显示“知识库中没有找到相关信息”。排查后发现，文档索引本身是正常的：知识库中有三份状态为 `ready` 的 VPN 排障文档，查询“VPN”可以检索到内容；但“工程规范”与现有材料没有直接的向量或关键词命中。

所以问题不在前端、索引任务或数据库，而在 Agent 对“知识库有内容，但问题超出资料范围”这一状态的表达不够准确。

## 2. 为什么不能直接让 Agent 根据 VPN 文档回答工程规范

RAG 的基本边界是：检索到的材料只能支撑与材料相关的回答。VPN 排障清单可以说明客户端版本、账号权限和网络连通性的检查步骤，但不能证明企业的代码规范、评审流程或发布规范。

如果 Agent 把 VPN 材料包装成工程规范，就是“看起来回答了，实际上没有依据”的幻觉。企业知识库中，这比明确说明资料不足更危险，因为员工可能据此执行错误流程。

## 3. 这次采用的处理逻辑

知识问答节点分成两层判断：

1. 先调用混合检索工具，寻找与用户问题直接相关的 chunk。
2. 如果没有直接命中，再从当前知识库读取最多三段来自 `ready` 文档的样本，只用于说明资料覆盖范围。
3. 有样本时，Agent 返回“现有资料未覆盖该主题”，同时展示真实文档名和引用片段。
4. 没有任何 `ready` 文档时，才返回“知识库中没有找到相关信息”。

这里的“范围样本”会标记 `sources=["knowledge_base_scope"]` 且 `score=0.0`。它不是检索结果，也不能被误解为“这段材料回答了当前问题”。

## 4. 代码如何分层

- `DocumentChunkRepository.list_ready_for_knowledge_base()`：只读查询某个知识库中已索引文档的少量 chunk。
- `DatabaseKnowledgeBaseScopeTool`：把数据库模型转换为 Agent 可序列化的引用对象。
- `answer_knowledge_question()`：根据“直接检索命中 / 仅有范围样本 / 空知识库”选择不同回答。
- `tasks/agent.py`：在每次请求创建 Agent 运行时，把范围工具注入工作流依赖。

这种拆分使工作流不知道 SQLAlchemy 细节，仓储层也不需要知道对话措辞；后续要改成按文档标题汇总范围，或增加知识库覆盖率指标，都不会影响向量检索接口。

## 5. 如何验证

新增测试覆盖三种情况：

1. 有直接检索命中时，仍使用 Chat 模型依据引用回答。
2. 没有直接命中、但知识库有已就绪文档时，返回范围不足说明和真实引用。
3. 没有直接命中、知识库也没有已就绪文档时，保留空知识库提示。

工具层测试还验证范围工具会正确标记引用来源，不会把它们伪装成向量或关键词命中。

## 6. 面试时可以怎样介绍

> 我在 RAG Agent 中区分了“检索为空”和“知识库为空”两个状态。前者说明用户问题超出了当前资料覆盖范围，后者才说明没有可用资料。实现上，我先走混合检索；没有命中时再只读抽取已就绪文档样本，作为覆盖范围证据，并把它标记为非检索来源。这样既让用户知道知识库里有什么，也避免让模型根据无关材料编造答案。
